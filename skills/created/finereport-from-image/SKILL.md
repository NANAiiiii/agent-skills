# 图片转 FineReport 原生驾驶舱

把用户的参考图片实现为可编辑、可取数、能正常预览的原生 `.frm`。图片是视觉基准，用户最新指令优先；卡片数量、业务主题、指标顺序、数值上下位置由本次图片决定。

## 开始前确认当前状态

- 读取参考图片；识别卡片网格、页面比例、标题、指标、单位、图表类型、图例、坐标轴、强调框、间距和颜色。能辨认的文字准确转录；无法辨认且会改变业务含义的内容向用户确认，其余小差异说明采用的假设。
- 发现实际 FineReport 安装位置、版本、reportlets 目录、可用连接和预览入口。不要假定盘符、连接名、端口或账号密码。
- 区分新建与修改。新建时检查目标文件是否存在，未授权覆盖则另存。修改时以部署目录最新文件为准，先备份并记录哈希；写回前确认源文件没有再次变化。保留用户新增的数据集、组件和样式，不用旧生成脚本重建覆盖。
- 只做驾驶舱 `.frm`；若用户明确要求 `.cpt`，说明该技能的范围并按用户目标选择其他实现方式。

## 原生构建和数据

编辑 XML 或复制组件前，阅读 [原生结构与排错](references/native-format.md)。优先复用目标环境中能加载的官方组件结构，也可从 [原生参考模板](assets/reference-dashboard.frm) 提取组件。参考模板是演示素材，不是每个新页面的固定布局，也不要修改技能内的素材。

- 使用原生绝对布局容器、标签、`ElementCaseEditor` 报表块和 `ChartEditor` 图表。保留 `.frm` 必需结构与版本标记，按实际组件 class 定位，不只按名称选择。
- 不注入 JavaScript 事件、HTML组件或整图背景来代替原生报表。脚本仅用于生成和验证文件，不进入报表运行逻辑。清理复制组件携带的活动回调、外部链接及无效图片边框。
- 业务数值（主指标、同比环比、补充值、页脚数值）通过 `DSColumn` 展示；图表直接绑定数据集字段。文字、单位、轴刻度、图例和图形装饰可为静态内容。不要使用 `dataset.select(...)` 公式或静态标签冒充指标取数。
- 用户未提供真实数据源时，使用少量 Greenplum 兼容 `SELECT … UNION ALL` 常量数据。指标数据集通常一行，月度图表通常一个数据集返回所有期间；数量按图片需要确定。避免新建业务表。百分比存小数，金额和数量保持数值类型，通过原生显示格式处理。
- 连接到本机能执行查询的连接以验证；迁移说明列明实际连接别名及替换位置。用户提供真实连接、表和口径时按其要求使用，不擅自换成演示数据。SQL兼容声明不等于已在 Greenplum 实例执行。
- 先在工作区生成候选文件。对现有报表只修改本次相关节点，并比较数据集、绑定、图表配置等应保持不变的部分。

## 视觉还原

按截图比例建立画布与网格，决定字体层级、卡片内边距、组件间距及图表占比。不要额外加标题栏、导航、总览或水印。截图中的强调元素按用户意图保留。

- 指标数值与名称分层、对齐；名称在上或在下按本次要求。单位不能与数字分离过远或压住相邻指标。
- 柱线组合图的金额和比例使用正确的独立坐标轴；百分比、数量和天数的范围、单位和标签与数据对应。清理组件继承的主题覆盖、渐变、标题和默认配色。
- 使用原生背景和细实线。避免用大量偏移叠层模拟阴影或用加粗掩盖缺线。复制的空图片边框必须移除。边框四边的连续性、透明度、层级和实际缩放结果都要检查，XML宽度相同不代表物理像素视觉一致。
- 图表、标签和报表块应放得下内容。检查报表块的实际列宽行高，而不是通过隐藏 overflow 来掩盖截断。页面可纵向滚动，卡片内部默认不应出现滚动条。

## 验证与修正

先运行只读检查器：

```text
python scripts/inspect_frm.py <候选文件.frm> --json <工作区检查结果.json>
```

检查器报告结构问题、数据集引用和静态数字候选；它不能证明 SQL 已执行、所有字段都存在或视觉相似。需要逐个审查警告，不能仅凭退出码宣称完成。

部署到用户指定的目录后，实际预览。可使用现有浏览器工具，或使用参数化脚本（Node.js + Playwright）：

```text
node scripts/preview_frm.cjs --base-url <工程根地址> --template <reportlets相对路径.frm> --out <工作区截图目录> --design-size <宽x高> --widths 1366,1550,1920
```

工程根地址例如 `http://localhost:<端口>/webroot`。`--playwright-path` 可指定已安装的 Playwright 模块，`--browser-executable` 可指定本机 Chrome；先发现已有运行时，不自行下载安装。可用 `--card-selector`、`--expect-widgets`、`--chart-widgets` 根据本次结构检查，不固定卡片数量或名称。

`--expect-widgets` 用于能从原生 DOM 名称或图表ID观察到的组件。部分11.x版本的报表块没有名称属性，脚本通过 `reportBlocks` 记录其位置；对这些块使用截图检查，不能以猜测的DOM名字断言缺失或加载成功。

认证默认使用未登录会话，也可读取用户授权的外部 `--storage-state`。只有用户授权自动登录且提供了凭据时，才通过进程环境 `FR_PREVIEW_USER`、`FR_PREVIEW_PASSWORD` 传入；不写进报表、技能、脚本、命令行参数或检查结果。登录受阻时报告 `auth_required`，不要把登录页截图当作报表通过。

验收应包含：

- 设计器能打开（环境可用时）；服务器实际预览显示全部期望组件；数据集和图表正常取数。
- 默认在1366、1550、1920px宽度及100%浏览器缩放下检查。根据实际设计尺寸生成截图，并打开查看，核对所有卡片、边框、单位、图例、趋势和页脚。需要时补充关键区域放大图；自动滚动检测不证明视觉没有截断。
- 检查浏览器错误、失败请求及预览期间新增的服务器日志，特别是模板解析、SQL、字段、图表和自适应异常。发现问题修复后重测受影响部分。
- 对应明确区分“XML检查通过”“服务器预览通过”“设计器打开通过”。接口不可用、服务未启动或凭据缺失时，完成可验证部分并准确报告未验证项，不编造截图或结果。

## 交付

交付部署文件、工作区 `outputs` 副本、实际预览截图、数据集 SQL 和必要的连接迁移说明，核对部署与副本哈希。说明与参考图的实质差异及未完成验证项；不要把后台接口返回成功或单次截图作为全部组件已验证的证据。
